# Persona canonical photo wizard - 2026-08-09

## Цель

Встроить Cloudflare Workers AI непосредственно в жизненный цикл Персоны и превратить генерацию базовых фотографий в управляемый канонический процесс, а не в отдельную ручную AI-песочницу.

Отдельный `#/ai` сохраняется как диагностический и свободный генератор. Основной пользовательский поток теперь находится в `Персона -> Фото`.

## Резервная точка

Перед изменениями создана ветка:

`backup/dev-2026-08-09-pre-persona-photo-generator`

Она указывает на состояние `refactor/domain-catalog-v2` до интеграции мастера.

## Проверенная существующая архитектура

Supabase уже содержит необходимые сущности и роли, поэтому миграция БД не требуется:

- `characters` - сохраненные Персоны;
- `character_parameter_values` - нормализованные значения параметров;
- `assets` - метаданные файлов;
- `character_assets` - связь изображений с Персоной;
- поддерживаемые роли включают `face_closeup`, `portrait`, `full_front`, `full_back`, `profile_left`, `profile_right`, `reference`;
- `reference_status=canonical` уже является штатным статусом канонического изображения.

Физические изображения по текущей архитектуре остаются на InfinityFree, а Supabase хранит метаданные и связи.

## Пять канонических кадров

Мастер выполняется последовательно:

1. `face_closeup` - лицо крупно;
2. `portrait` - портрет / торс;
3. `full_front` - полный рост спереди;
4. `full_back` - полный рост сзади;
5. `profile_left` - профиль в полный рост.

Следующий шаг блокируется, пока предыдущие кадры не сохранены. После сохранения кадр получает `reference_status=canonical` и используется как доступный визуальный референс для следующих шагов.

## Селективный контекст prompt

Чтобы не передавать модели нерелевантные параметры, prompt builder делит CharacterState по типу кадра.

### Face close-up

Передаются:

- возраст;
- пол;
- этнический тип;
- тон и детали кожи;
- цвет глаз;
- длина, тип, прическа, цвет и детали волос;
- форма головы и лба;
- форма и густота бровей;
- форма, размер и расстояние глаз;
- форма и размер носа;
- форма губ;
- скулы;
- подбородок;
- макияж;
- постоянные особенности.

Не передаются рост, вес, обхваты, процент жира, параметры груди/ягодиц и татуировки вне кадра.

### Portrait / torso

Передается весь контекст лица плюс:

- грудь;
- талия;
- процент жира;
- мышечная масса;
- для женской Персоны - размер, форма и упругость груди;
- татуировки, если они могут быть видны в таком кадрировании.

Не передаются рост, вес, бедра и параметры ягодиц.

### Full body

Передается весь контекст лица плюс полная антропометрия:

- рост;
- вес;
- грудь;
- талия;
- бедра;
- процент жира;
- мышечная масса;
- женские параметры груди и ягодиц;
- татуировки;
- постоянные особенности.

Такой набор используется для `full_front`, `full_back` и `profile_left`, а shot instruction отдельно фиксирует нужный ракурс.

## Базовый генерационный комплект

Для совершеннолетней Персоны по умолчанию используется временный нейтральный комплект:

- непрозрачный облегающий бежевый спортивный короткий топ;
- короткие облегающие спортивные шорты;
- матовая ткань;
- без логотипов, принтов, аксессуаров и верхней одежды.

Комплект нужен только для читаемого силуэта и явно помечается в prompt как временная calibration clothing. Он не изменяет текущий Образ и не становится постоянным свойством Персоны.

Для Персоны младше 18 лет автоматически используется более закрытый вариант: бежевая спортивная футболка и шорты до колена.

## Визуальные референсы

Cloudflare FLUX.2 Klein принимает максимум 4 изображения. Wizard выбирает их по роли и качеству:

- `canonical` выше `approved`;
- `approved` выше `reference_only`;
- затем обычные non-rejected assets;
- учитывается `is_primary`;
- rejected assets исключаются.

Пример порядка для вида сзади:

1. `full_front`;
2. `face_closeup`;
3. `portrait`;
4. дополнительный `reference`.

В prompt явно указано не копировать из референсов случайный фон, освещение, позу или одежду.

## Сохранение

Новый результат сначала существует только в памяти браузера. Пользователь может:

- принять;
- перегенерировать;
- сохранить как канон.

При сохранении:

1. изображение загружается через существующий InfinityFree media repository;
2. создается asset metadata и `character_assets` relation через штатный Core/Supabase RPC;
3. новый asset получает `reference_status=canonical`;
4. `face_closeup` и `full_front` помечаются как primary для соответствующего типа референса;
5. старые assets того же слота удаляются только после успешной загрузки нового файла;
6. мастер автоматически переходит к следующему шагу.

## Безопасность токена

Cloudflare API Token:

- не коммитится в GitHub;
- не записывается в Supabase;
- не записывается в Zustand persistence или localStorage;
- хранится только в памяти текущего SPA-сеанса;
- может переиспользоваться между отдельной страницей `AI` и встроенным мастером Персоны, пока страница не перезагружена.

## Производительность

Мастер монтируется только при открытии вкладки `Фото`.

До этого он не:

- загружает character assets;
- запрашивает публичную библиотеку Персон;
- скачивает изображения-референсы;
- обращается к Cloudflare.

Сами референсы скачиваются и уменьшаются до требований Cloudflare только непосредственно перед генерацией текущего шага.

## Регрессионные тесты

Добавлен `persona-photo-generator.prompt.test.ts`, который фиксирует границы контекста:

- лицо не получает параметры тела;
- торс не получает рост, вес, бедра и параметры ягодиц;
- полный рост получает всю антропометрию;
- последовательные reference roles добавляются в prompt;
- базовый бежевый комплект присутствует только там, где нужен телесный референс;
- для несовершеннолетнего профиля применяется закрытый calibration outfit.
